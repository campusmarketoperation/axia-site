# AXIA Shift

飲食店向けのシフト管理SaaS。バイトはURLかLINEから希望を出し、店長はWebの表で時間を決めて確定・LINE配信、本部は全店の過不足を見てヘルプを頼めます。運営（AXIA）は管理画面で契約会社を管理します。

- **画面**：Next.js 14（App Router）
- **データとログイン**：Supabase（Postgres・メールのログインリンク）
- **公開**：Vercel
- **LINE**：Messaging API（ボット1つで全部の会社・店舗を受け付ける）

---

## 画面と、使う人

| URL | 使う人 | できること |
|---|---|---|
| `/admin` | 運営（AXIA） | 契約会社の一覧・追加、状態（お試し／契約中／停止中）、月額、本部の招待、利用停止、支払い、会社の削除（データをすべて消す） |
| `/hq` | 本部 | 全店の過不足、ヘルプを頼む・取り消す、店長グループへの文面、店舗の追加、店長・本部の招待 |
| `/store/[id]` | 店長 | シフト表（マスを押して時間・✖・カット）、確定、全員にLINEで送る、画像で保存、提出のお願いをLINEで送る（締め切り付き・全員／未提出／選んだ人） |
| `/store/[id]/help` | 店長 | ヘルプの依頼の承認・断る、行く／来てもらうヘルプの一覧、人ごとの「ヘルプに行ける店」 |
| `/store/[id]/neighbors` | 店長 | 近隣の店の出れる人数と、ヘルプOKの人の行ける日。行ける日を押すと自分の店のヘルプを頼める |
| `/store/[id]/members` | 店長 | メンバーの追加・並べ替え・社員/アルバイト・辞めた人・LINE登録の解除 |
| `/store/[id]/settings` | 店長・本部 | 期間の区切り、入り時間、必要人数、社員の選択肢、近隣の店（本部だけ）、提出URLとLINE登録コード |
| `/s/[token]` | バイト | シフト提出（ログイン不要） |
| `/api/line/webhook` | LINE | ボットの受け口 |

権限：店長は自分の店だけ。本部は自分の会社の全店（会社ごとに「本部も店のシフトを変えられる」をオフにすると、本部は見るだけ）。運営は全部。会社を「停止中」にすると、その会社の画面・提出URL・LINEが止まります。

## 導入手順

### 1. Supabase

1. [supabase.com](https://supabase.com) で新しいプロジェクトを作る（リージョンは Tokyo）
2. **SQL Editor** を開いて、`supabase/migrations/001_init.sql` の中身を貼って **Run**
   - あとから追加したファイル（`002_help_enabled.sql` など）も、番号の順に貼って **Run**
3. **Authentication → URL Configuration**
   - Site URL：公開するURL（例 `https://axia-shift.vercel.app`）
   - Redirect URLs：`https://axia-shift.vercel.app/auth/callback` を追加
4. **Project Settings → API** から次の3つを控える
   - Project URL → `NEXT_PUBLIC_SUPABASE_URL`
   - anon public → `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - service_role → `SUPABASE_SERVICE_ROLE_KEY`（**絶対に外に出さない**）

> ログインメールは、最初は Supabase の標準のメール送信で動きますが、送れる数がかなり少なく制限されています。お客さんに使ってもらう前に **Authentication → SMTP Settings** で自前のメール送信（Resend など）を設定してください。

### 2. Vercel

1. このフォルダを GitHub のリポジトリに入れる
2. [vercel.com](https://vercel.com) で **Add New → Project** → そのリポジトリを選ぶ
3. **Environment Variables** に `.env.example` の項目を全部入れる

| 名前 | 中身 |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | SupabaseのProject URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon public |
| `SUPABASE_SERVICE_ROLE_KEY` | service_role |
| `NEXT_PUBLIC_SITE_URL` | 公開URL（最後に / を付けない） |
| `LINE_CHANNEL_SECRET` | LINEのチャネルシークレット |
| `LINE_CHANNEL_ACCESS_TOKEN` | LINEのチャネルアクセストークン（長期） |
| `ADMIN_EMAILS` | 運営画面に入れる人のメール（カンマ区切り） |

4. **Deploy**

### 3. LINE

1. LINE Official Account Manager で公式アカウントを作る（名前は「AXIA Shift」など、どの会社でも使える名前に）
2. 設定 → Messaging API → **利用する**
3. LINE Developers → そのチャネル → **Messaging API設定**
   - チャネルアクセストークン（長期）を発行 → `LINE_CHANNEL_ACCESS_TOKEN`
   - Webhook URL：`https://<公開URL>/api/line/webhook` → **Webhookの利用：オン**
   - 「検証」で成功と出ればOK
4. **チャネル基本設定** のチャネルシークレット → `LINE_CHANNEL_SECRET`
5. LINE Official Account Manager → 応答設定：**応答メッセージ オフ**、**あいさつメッセージ オフ**、**Webhook オン**
6. Vercel の環境変数を入れたら **Redeploy**

### 4. 最初のログインと会社の追加

ログインはメールアドレス＋パスワード。招待メールやログイン用リンクから初めて入った人は、パスワードを決める画面（`/account/password`）に進みます。パスワードを忘れた時は、ログイン画面の「ログイン用のリンクをメールで送る」から入って、左下の「パスワード変更」で決め直します。


1. `https://<公開URL>/login` を開いて、`ADMIN_EMAILS` に入れたメールでログイン
2. 運営の管理画面 → **会社を追加**（会社名・最初の店舗・本部の人のメール）
3. 本部の人に招待メールが届く → 本部の人がログイン → `/hq` で店舗を追加・店長を招待
4. 店長は **店舗の設定** で期間の区切り・入り時間・必要人数を決めて、
   - 「シフト提出画面のURL」をグループLINEに貼る
   - LINEで出したい人には、ボットを友だち追加して「登録コード（6けた）」を送ってもらう

## LINEボットでできること

- 店長・本部は「ヘルプ」画面（本部は本部画面）の **LINEでつなぐ** → ボットに「通知 123456」と送ると、ヘルプの依頼・承認・お断りが LINE で届く

- 登録：友だち追加 → 店の登録コード → 名前（番号か名前、リストにない人は「名前 山田」） → ヘルプに行ける店（番号・全部・なし。あとで「ヘルプの店」で変えられる）
- 提出：`11,16,17,24,25` ＋ `時間何時でもいいです`（書いてない日は✖）、曜日ごとの時間 `平日は6時から、金土日は何時でも`（「月〜木」「土日」「それ以外」も可）、`27 5`、`28 ✖`、`11/1〜11/3 ✖`、`残り✖`
- 出したあとにヘルプの確認（ボタン、または「はい」「無理」などの返事）
- `確認`（自分の希望）、`確定シフト`、`メンバー`（今日と明日に出勤する人）、`明日のメンバー`、`10/17 メンバー`、`使い方`、`名前変更`
- 店長が「全員にLINEで送る」→ 一人ずつに確定シフト
- ヘルプは「依頼（本部・ヘルプ先の店長）→ 所属店の店長が承認 → ヘルプ先の店長が入り時間を決める」。承認された時と、入り時間が決まった・変わった時に本人にLINEで連絡

プッシュ送信（確定シフト・ヘルプの連絡）は LINE の月の通数に数えられます。返信は数えられません。運営画面に会社ごとの今月の送信数が出ます。

## ルール（GAS版と同じ）

- 期間は店ごとの区切り日で2つ（例：11〜25日／26〜翌月10日）。使い始めたら変えない
- マスの値：入り時間（`5〜` `4:30〜`）、`○`（何時でも）、`✖`（本人が無理）、`カット`（出れるけど店で入れなかった）
- 出れる人数は、バイトの時間と○の日＋社員の出勤日＋他店からのヘルプ（必要人数も社員込み）。必要人数より少ない日は赤
- 店舗の設定で「他の店へのヘルプを募集する」をオフにすると、提出画面とLINEでヘルプOKを聞かず、その店の人はヘルプ要員として出ない
- 社員の行は空白＝出勤。店舗の設定で「休みの選択肢」（休・有給・公休など）と「出勤の選択肢」（早番・遅番・研修など）を分けて決める。休みの選択肢だけが出れる人数から外れる
- 近隣・本部から見た時、確定済みの店は「空白・カット」の日を行ける日として扱う
- 所属店のシフト表では、ヘルプに行く日は「漁火5〜」のように行き先＋時間で出る
- シフト表の「ヘルプに出す」の行で、店長が日ごとに出せる／出せないを決める（決めていない日は自動：未確定は余裕がある日、確定済みはカットの人がいる日）。出せない日は、ほかの店の店長からは頼めない（本部は注意付きで頼める）

## 開発

```bash
cp .env.example .env.local   # 中身を入れる
npm install
npm run dev                  # http://localhost:3000
npm run build                # 本番ビルド（型チェック込み）
```

ブラウザからデータベースを直接読めないように、全テーブルで RLS を有効にしてポリシーを作っていません。読み書きはすべてサーバー側（service role）で、権限はアプリの中（`lib/auth.ts`）で確認しています。

## GAS版（スプレッドシート）からの移し替え

1. 新しい方で店舗を作る（運営画面か本部画面）。店長画面のURL `/store/<ID>` の `<ID>` を控える
2. 移したい店のスプレッドシート → 拡張機能 → Apps Script → ＋ → スクリプト（名前 `export`）に `scripts/export-from-gas.gs` を貼る
3. `exportForSaaS` を選んで ▶ 実行 → ログに出るURLから JSON をダウンロード
4. パソコンで
   ```bash
   node scripts/gas-to-sql.mjs "AXIA Shift 移行データ_妻籠.json" --store <ID> > import.sql
   ```
5. `import.sql` の中身を Supabase の SQL Editor に貼って Run

移るもの：メンバーと順番、社員、提出された希望（入り時間・ヘルプOK）、店長がシフト表で直したマス、確定のチェック、期間の区切り・入り時間・社員の選択肢。
何回流しても大丈夫です（同じ名前の人は作り直さず、上書きします）。

LINE登録も移したい時は `--with-line` を付けます。ただし**新しいボットが前と同じプロバイダーのチャネルの時だけ**つながります（LINEのユーザーIDはプロバイダーごとに違うため）。別のプロバイダーなら、バイトの人に新しいボットで登録し直してもらってください。

## お支払い（Stripe）

会社ごとに「1店舗の月額 × 店舗数」を毎月請求します。払い方は運営画面で会社ごとに選びます。

- **カード自動払い**：本部画面の「お支払い」→ カードを登録して申し込む（お試し中に登録しても、お試しが終わるまで請求されない）
- **請求書（銀行振込）**：運営画面の「お支払い」→ 送り先メール・支払い期限を入れて「請求書払いで始める」。毎月請求書がメールで届き、会社ごとの専用口座への振込は自動で消し込まれる
- 店舗の追加・月額の変更は、次の請求から反映（日割りなし）
- 支払いが遅れても自動では止めない。運営画面に「期限切れ」と出る。会社を開いた「未払いの対応」で：
  - **お知らせを出す**：本部・店長の画面の上に「お支払いが確認できていません」（停止予定日を入れると、その日に自動で停止）
  - **今すぐ停止／再開する**、**請求書をもう一度送る**、**サブスクを解約**
  - 支払いが確認できたら、お知らせと停止予定は自動で取り消し。未払いで停止していた会社は自動で再開
- 停止中の会社は、ログイン・提出画面・LINE がすべて止まり、「ご利用が停止されています」と出る
- 設定：`supabase/migrations/005_billing_lock.sql` も Run

設定：
1. Supabase の SQL Editor で `supabase/migrations/004_billing.sql` を Run
2. Stripe ダッシュボード（テストモード）
   - 設定 → 支払い方法：**銀行振込**を有効にする
   - 設定 → Billing → カスタマーポータル：有効にして保存
   - 設定 → Billing → 請求書・メール：確定した請求書を顧客にメールで送る、をオン
   - 開発者 → Webhook → エンドポイントを追加：`https://<公開URL>/api/stripe/webhook`、イベントは `checkout.session.completed`、`customer.subscription.created / updated / deleted`、`invoice.finalized / paid / payment_failed / overdue / voided / marked_uncollectible`
3. Vercel の環境変数：`STRIPE_SECRET_KEY`、`NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY`、`STRIPE_WEBHOOK_SECRET` → Redeploy
4. 本番に切り替える時は、本番モードで 2 を同じようにやって、鍵を `sk_live_` などに入れ替える

## 締め切り当日の自動リマインド
- 毎日22時ごろ（Vercel Cron：`vercel.json`）に `/api/cron/remind` が動く
- その店・期間の締め切り日（店長画面の「提出のお願い」で決める。決めていなければ期間開始の5日前）が今日なら、
  未提出のバイトには提出のお願い、提出済みのバイトには出した希望の確認を LINE で送る（1期間1回。締め切り済み・確定済みなら送らない）
- Vercel の環境変数に `CRON_SECRET`（長いランダムな文字列）を入れる
